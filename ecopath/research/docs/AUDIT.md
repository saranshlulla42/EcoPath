# Audit of the original EcoPath experiment

Inspected 20 October 2026. Machine-readable evidence: `../artifacts/original/manifest.json`, `../artifacts/original/audit/audit.json`, the full species inventory, recomputed row metrics, and saved tokenizer diagnostics. Paths in manifests are relative to the Capstone repository root. Original records were read without modifying them; pickle files were inspected statically rather than deserialized.

## What exists

The platform is Next.js/React/TypeScript with MapLibre/deck.gl/Recharts, backed by FastAPI/Pydantic/httpx, Supabase/Postgres, a tool-using Gemini agent, and local Ollama report synthesis. A shared data layer handles caching, provenance envelopes and source adapters; a newer precompute layer includes DuckDB-based data products. These are implemented code paths, not proof of successful deployment or ecological validity.

The current report service resolves GBIF identity, enriches profile fields, gathers IUCN/Wikidata, Wikipedia, news RSS and GDELT context, derives heuristics, runs a short JSON analysis and a longer prose stage, then repairs and merges model and fallback content. It is a different system from the saved HF evaluation. Family threat hints, regex extractions, occurrence summaries, source normalization and fallback prose can add content that was never generated or verified by the model. Do not attribute hybrid application reliability to QLoRA alone.

The saved experiment is in `ecopath_afterJudge-20260902T160124Z-1-001/ecopath_afterJudge/`: dataset, training/evaluation/grading/export scripts, 85/15 split, checkpoints 25/30/33, adapter, raw outputs, individual judge scores, aggregate reports and figures. `ecopath/final` contains byte-identical adapter weights to the archived final adapter. A merged-model directory also exists; its contents are referenced in the original manifest. The dataset builder referenced by the scripts (`generate_synthetic_dataset.py`) and its input species list are absent. No TeX/DOCX source for the 0/15 versus 15/15 manuscript was found. Available manuscript-like sources are `EcoPath_Report_Corrected.md` and `research_paper_technical_methodology.txt`; the former is an earlier broad platform report and contains no QLoRA results section.

## Dataset and provenance

Verified: 100 records, 100 unique scientific names, 31 families, 16 orders, 85 training species and 15 evaluation species. No species overlaps those saved splits. **Larus and Turdus occur in both**, so this is not a genus-held-out study. No separate validation split or validation checkpoint-selection record exists. Species selection, exclusions, India membership and geographic coverage are unavailable. The names span a broad global catalogue; do not describe these 100 records as a verified Indian sampling frame.

All 100 input profiles contain GBIF key, names, family and order. Across all 100, IUCN status, population size/trend, habitat, range, diet, breeding and migration fields are absent. Every `search_results` item is labelled GBIF (100 total); the snippets state taxonomy. `source_mode=gbif+gdelt` and threat-oriented search queries do **not** show GDELT evidence was supplied. IUCN, news, Wikipedia, eBird, Movebank and weather are platform connections, not recorded ecological sources in this experiment.

GBIF URLs and taxonomy snippets exist. `seendate` is null throughout; dataset `created_at` timestamps are creation metadata, not verified retrieval timestamps. Source record IDs can be recovered from GBIF keys/URLs, but original dataset version/DOI, access licence records, query responses and ecological assessment provenance were not logged. No ecological labels should be filled retrospectively from a model's prior knowledge.

Targets are teacher-written JSON, not independently verified reference assessments. All 100 contain heuristic-language tokens; inspected examples refer to an elevating risk direction or localized/regional pressure absent from the taxonomy-only input. Those are concrete reasons to review targets before reuse. The filename suggests a Gemini teacher, but the exact teacher identifier, prompts, settings, retries and processing implementation are unavailable. Do not present provider naming as an exact model record.

## Training: records versus code defaults

The adapter names `Qwen/Qwen2.5-7B-Instruct`; PEFT configuration records LoRA rank 16, alpha 32, dropout .05, no bias, and q/k/v/o/up/down/gate projection targets. The script specifies NF4, double quantisation, 4-bit loading and fp16/bf16 compute selection. The immutable base/tokenizer revision is not recorded. Adapter PEFT metadata is not a complete training environment record.

Direct scalar inspection of both saved `training_args.bin` files records batch 1, accumulation 8, learning rate .0002, three epochs, seed 42, fp16 true, bf16 false, warmup_steps 1, logging_steps 10, save_steps 5, and load_best_model_at_end false. Trainer's gradient_checkpointing flag is false; the script separately calls `model.gradient_checkpointing_enable()`, so that flag alone cannot establish actual model checkpointing behavior. Script defaults of save_steps 100 and max sequence length 4096 must not be presented as observed run settings. Sequence length is not recorded in TrainingArguments.

Checkpoint 33 records epoch 3 and step 33, with training loss observations 1.43736 at step 10, .555119 at 20 and .375935 at 30. These are training losses, not validation loss, perplexity, evidence fidelity or convergence guarantees. No best validation checkpoint is recorded. Training GPU model, wall time, GPU hours, peak memory and original complete package environment are unavailable. Do not infer hardware from a Colab-oriented filename or script comments.

## The 0/15 versus 15/15 result

Re-running parsing over saved raw responses reproduces strict JSON validity **0/15 base and 15/15 adapted**. The original forgiving parser gives the same counts. Its alleged schema metric checks six required key names, allows flat or nested layouts and checks no field types, citation semantics or full schema. The adapted outputs therefore satisfy a key-presence check, not demonstrated full schema compliance or evidence fidelity.

The preserved evaluation script applies the tokenizer's chat template to both methods and constructs the same evidence/prompt for each. Both generation calls use the same function and configured arguments. This supports comparability of the code path; the exact effective CLI settings, immutable model revision, stochastic seed, finish reasons and token IDs are absent from saved outputs. Default decoding is sampling at temperature .1 with 1024 new tokens. The prompt requests a structured report, but contains neither an explicit JSON requirement/schema nor examples. Base outputs are ordinary report prose. That is a weak baseline for claiming that adaptation is required for JSON.

Training manually serializes `<|system|>`, `<|user|>`, `<|assistant|>` and `<|end|>`. The saved Qwen tokenizer registers none of these as special tokens; its native markers are `<|im_start|>` and `<|im_end|>`. This format mismatch is verified, but its causal contribution to model behavior requires a controlled ablation. CPU reconstruction with the saved tokenizer finds training lengths 747–1478 tokens, so none would exceed the **script default** of 4096; that does not recover the effective original sequence setting. Saved-tokenizer checks find no duplicate-special-token difference for the original evaluation tokenization path. Finish reasons were not logged, so output truncation cannot be ruled in/out from original generation records. Retokenized decoded-text lengths are diagnostics, not measured generation counts.

`tokenizer_diagnostics.json` was an intermediate diagnostic with a Transformers return-type error: it counted BatchEncoding keys. It is superseded by `tokenizer_diagnostics.v2.json`. This software-check failure is retained for traceability; only v2 measurements are used here.

The judge rubric blends ecological plausibility and evidence grounding. `score_row` passes only `prompt_user[:600]`; the later function's 800-character limit cannot restore lost evidence. Actual SEARCH RESULTS generally appear later. Judge scores therefore do not establish supplied-evidence fidelity. The script default is `gemini-3.6-flash`, temperature 0, with retries, but effective judge identity/settings/retries were not preserved per result. Batch score files retain individual scores/reasons; the script can turn judge failures into zero-score dictionaries. No human validation, adjudication or independent-judge evidence exists. Teacher–judge provider overlap is possible; exact model overlap is unknown.

## Supported interpretation and revision consequences

The records support a formatting difference under one weak original prompting condition on 15 taxonomy-only examples. They do not establish improved conservation accuracy, available-field use, citation support, resistance to false abstention, superiority to strong prompting or constrained decoding, cost advantage, Indian ecological generalisation, or validated human usefulness. No status accuracy can be computed when every source status is missing. Do not label this saved evidence-in-prompt comparison RAG: it performs no retrieval at evaluation time.

The legacy application still needs human review of unconstrained prose and heuristic ecological claims. The new preview and evaluation contract check structured assertions and citations, distinguish null from official NE/DD categories, and label proposals separately. Their tests establish software behavior; real ecological fidelity remains an empirical question.
